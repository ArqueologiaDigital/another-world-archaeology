# Issue Tracker — Schema

This is the canonical issue tracker for the project. The source of
truth is the individual `<NNNN>-<slug>.md` files in this directory;
`README.md` is **auto-generated** by `tools/issues.py index` and
must never be edited by hand.

## File naming

`<NNNN>-<slug>.md`

- `<NNNN>` is a 4-digit zero-padded **stable** ID. Once assigned,
  it's permanent — even after the issue is closed. New issues
  always take the next available ID. Numbers are never reused.
- `<slug>` is a short kebab-case description. The slug **may** be
  edited later for clarity; the ID may not.

## Frontmatter (required)

```markdown
---
id: 0042
title: Short imperative-mood title that fits on one line
status: open
tier: A
created: 2026-04-30
updated: 2026-04-30
depends_on: [0017, 0029]
blocks: [0098]
tags: [extractor, mac, research]
---
```

### Field semantics

| Field | Required | Values |
|---|---|---|
| `id` | yes | 4-digit zero-padded; must match filename prefix |
| `title` | yes | one-line imperative-mood description |
| `status` | yes | `open`, `in-progress`, `blocked`, `done`, `wontfix` |
| `tier` | yes | `A` (high research ROI), `B` (format work), `C` (acquisition), `D` (infra), `none` |
| `created` | yes | ISO date `YYYY-MM-DD` of opening |
| `updated` | yes | ISO date of last meaningful change |
| `depends_on` | no | list of IDs that must complete before this one is actionable |
| `blocks` | no | list of IDs that this one is blocking |
| `tags` | no | free-form lowercase-hyphenated keywords |
| `closes_pr` | no | git commit / PR identifier when status flipped to `done` |

## Body structure (recommended)

```markdown
# Context

Why this exists, what motivated it, what we know already.

# Acceptance criteria

- [ ] Specific deliverable 1
- [ ] Specific deliverable 2

# Log

- 2026-04-30: opened
- 2026-05-02: blocked on #0017
- 2026-05-10: started — see commit deadbeef
```

The **Log** section grows append-only as updates happen. Each
session that touches the issue adds a dated entry.

## Status semantics

- **`open`** — not started; ready to be picked up.
- **`in-progress`** — actively being worked on, has at least one
  in-flight commit on a branch or in a session.
- **`blocked`** — cannot proceed without a specific listed
  dependency or external action. The blocker should be named in
  the Log section.
- **`done`** — completed. The body's Log entry should record the
  resolution and reference the closing commit(s).
- **`wontfix`** — explicitly decided not to do. Log the reason.

**Issues are never deleted, only closed.** A wrong-direction issue
stays in the tracker as `wontfix` with a note explaining why.

## Strict policies

These are enforced by convention; `tools/issues.py validate` runs
the mechanical checks.

1. **Every loose end identified in conversation must become an
   issue before the conversation moves on.** No "I'll remember
   this" — write it down. Memory across sessions is unreliable;
   commits are reliable.

2. **The index is regenerated by tooling, not edited by hand.**
   Run `tools/issues.py index` before any commit that touches
   `issues/`. The auto-generated `README.md` lists open issues by
   tier and a status-tier matrix.

3. **IDs are forever.** A typo in a filename is fixable; an ID
   change breaks every cross-reference. Never reuse a number.

4. **No silent status changes.** When status flips, add a Log
   entry that records the date, reason, and (for `done`) the
   resolving commit hash.

5. **Issues stay in sync with reality.** When an extractor lands,
   close the corresponding issue in the same commit — the
   commit message references `closes #NNNN`. When a finding doc
   answers an open question, mention the issue ID.

6. **`tools/issues.py validate` must pass before committing.**
   It checks: filename↔frontmatter id consistency, required
   fields, valid status/tier values, all `depends_on` and
   `blocks` references resolve, no duplicate IDs.

## Tooling

- `python3 tools/issues.py list` — show issues, optionally
  filtered by `--status`, `--tier`, `--tag`.
- `python3 tools/issues.py new --title "…" --tier A` — create
  a new issue with the next available ID, opening editor on the
  template.
- `python3 tools/issues.py index` — regenerate `issues/README.md`.
- `python3 tools/issues.py validate` — verify all issues
  conform to the schema.
- `python3 tools/issues.py show <id>` — print an issue's
  metadata + body (path-resolves the ID).
