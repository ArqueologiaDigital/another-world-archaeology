# Cross-port sprite-byte diff artifacts

These JSON files are generated by `tools/cross_port_used_polygon_diff.py`
and `tools/attribute_cut_polygons.py`. They identify polygon
sprite-bytes that exist in one port's bank but not the other, with
semantic attribution where the per-branch sources have semantic
EQU names.

See [research/12](https://github.com/ArqueologiaDigital/another-world-source-reconstruction/blob/main/docs/content/research/12-cross-port-sprite-rebuild.md)
for the full archaeological discussion. Headline finding: the
1991→1992 port was a **sprite pipeline rebuild** — amiga's
per-stage detail sprites were unified into the shared
`COMMON_VIDEO` bank + composite helpers in DOS 1992, and every
post-1991 port (DOS 1992, SNES-EU 1992, Genesis-EU 1993, GBA 2004)
inherits that architecture.

## File contents

- **`cut_polygons_amiga_only.json`** — solid-polygon offsets in
  amiga's polygon banks that:
  1. Are USED by amiga's bytecode (directly via `video=1` refs or
     transitively via group-polygon children), AND
  2. Have no byte-matching equivalent in the corresponding DOS
     port's polygon bank.

  These are the "amiga-only" sprites — present in 1991, removed
  from 1992. Indexed by stage name (LAKE, CAPSULE, INTRO,
  PASSCODE).

- **`dos_added_polygons.json`** — same structure but reversed:
  solid-polygon offsets in DOS's polygon banks that are USED by
  DOS bytecode AND have no byte-matching equivalent in amiga's
  bank. The "DOS additions" — sprites that the 1992 rebuild
  introduced that weren't in the 1991 release.

- **`cut_attribution.json`** — per-stage attribution of the
  cut/added sub-polygons to named animation cycles. For each
  stage, walks the polygon hierarchy in reverse to find which
  parent group polygons contain each cut/added sub-poly, then
  matches those parent offsets to named EQUs in the per-branch
  source. The breakdown is structured as:

  ```
  {
    "cut_amiga_only_attribution": {
      "LAKE": {
        "n_target_children": 207,
        "n_parent_groups": 87,
        "by_animation_cycle": {
          "CINEMATIC_HERO_RESUME_LEFT": ["F0", "F1", ..., "F9"],
          "CINEMATIC_HERO_LEAP_LEFT": [...],
          ...
        }
      },
      ...
    },
    "dos_added_attribution": { ... }
  }
  ```

  LAKE has the highest-resolution attribution (86 of 87 parent
  groups map to named amiga animation cycles like HERO_RESUME_LEFT,
  HERO_LEAP_LEFT/RIGHT, POOL_LESTER, etc.). CAPSULE/TANK/CAVES
  attribution is shallower because their CINEMATIC_<NNN> EQUs
  haven't been semantically renamed yet.

## Tools that generate these

- `tools/cross_port_polygon_diff.py` — raw bank-content set diff
  (independent of bytecode reachability).
- `tools/cross_port_used_polygon_diff.py` — diff filtered to
  sprites actually USED by each port's bytecode. Higher signal.
- `tools/find_parent_polygons.py` — inverts polygon-walker's
  child→parent traversal.
- `tools/attribute_cut_polygons.py` — combines all of the above
  into the per-stage attribution report.

## Renderers (output not committed)

- `tools/polygon_render_png.py` — direct cairo PNG render of a
  single polygon.
- `tools/batch_render_cut_polys.py` — batch renderer that walks
  these JSON files and produces per-stage galleries with HTML
  contact-sheet indexes. Output lands in `tmp/cut_renders/` and
  `tmp/dos_added_renders/` (gitignored).
